SUID	4	Runs a file with its owner's privileges
SGID	2	Runs a file with its group's privileges; on directories, new items inherit the directory's group
Sticky Bit	1	Restricts who can delete files in a shared directory




sudo chmod 4766 test.txt


SUID (Set User ID) means an executable file runs with the permissions of its owner, not the user executing it.


A simple real-world use case of SUID between two normal users:
Use case: Shared project application
Suppose a company has two users:
- Rudra – owns a report-generating program.
- Rahul – needs to execute that program.
The program needs to write reports into a directory that only Rudra has permission to access.

Without SUID:
- Rahul executes the program.
- The program runs with Rahul's permissions.
- It cannot write into Rudra's protected directory.
With SUID:
- Rahul executes the program.
- The program runs with Rudra's effective user permissions.
- It can write reports into that directory.

=========================================================================================================
What happens after this?
Suppose Rudra, Rahul and Amit all use /company.
- All three can enter the directory.
- All three can create files.
- All three can read and modify files if file permissions allow it.
- But Rahul cannot delete Rudra's files.
- Amit cannot delete Rahul's files.
- Each user can delete their own files.
The directory owner and root can also delete files.
